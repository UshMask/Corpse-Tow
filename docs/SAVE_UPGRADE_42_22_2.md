# Исправление загрузки журнала на PZ 42.22.2

Проверено 14.11.2026. База: UshMask/Corpse-Tow main a892f588955edc88f9377df655ed39c651ba52d8.
Ветка: codex/fix-ledger-42222. Рабочий сервер, Workshop и игровые сохранения не изменялись.

## Подтверждённая причина

Фактические getter'ы установленной игры: 42.22.2, revision 3d39148846,
IsoWorld.getWorldVersion() = 251. На двух настоящих исторических CVPEquipment.bin
первые 10 байт: 43 56 50 45 51 31 00 00 00 f9. Это CVPEQ1 и big-endian version249.
Длины и SHA-256 payload корректны. Заголовок не повреждён.

Локальный установленный Workshop CorpseProxyWorld.jar побайтно совпадает с архивом
0.8.1: 128863 байта, SHA-256 fd52124c5882f9d81cabba07c9d3e27ef8b388e3a5850865da89d39de802ff24.
Его javap и исходники source-and-tests.zip совпадают по причине отказа:
одна IOException покрывает неверный MAGIC и неравенство world version.
На текущем движке оба настоящих файла воспроизводят IOException: unsupported equipment ledger.
Текущий GitHub main уже разделяет ошибки, но по-прежнему запрещал249→251.

## Исправление

- EquipmentPersistence передаёт KahluaTable.load версию из файла.
- Общий с ItemCodec список допускает только текущую версию либо проверенную пару249→251.
  Вложенные CVPITEM1:249 также читаются с их исходной версией; иначе загрузка журнала
  прошла бы, но восстановление исходного материала по-прежнему отказало бы.
- Ограничения длины, SHA-256, полного потребления payload, содержимого таблиц,
  native frame, ID, типа, registry и владельца сохранены.
- После успешной проверки старого журнала создаётся точная резервная копия
  CVPEquipment.bin.world-249.<SHA256 полного исходного файла>.bak.
  Существующий резерв проверяется побайтно и не перезаписывается. Повторное чтение
  не создаёт дополнительные резервы. Резерв сбрасывается на диск через force(true).
- Ошибка резервирования возвращает ошибку загрузки, не классифицируется как
  повреждение журнала и не запускает его сброс.
- Чтение не меняет исходный журнал. Следующая штатная атомарная запись создаёт
  версию251; сохранённые вложенные item snapshots249 остаются читаемыми.

## Воспроизведение

Запускать с локальными зависимостями игры, не на рабочем сервере:

```text
python tools/check_save_upgrade.py --game <ProjectZomboid> --jdk <JDK25> --zombie-buddy <ZombieBuddy.jar> --viewpoint <Viewpoint.jar> --ledger <old-CVPEquipment.bin>
```

--ledger можно повторить. Входные файлы только читаются; изменяются временные копии.
Без --ledger остаётся genuine old item fixture и явно синтетический журнал.
Логи сохраняются в напечатанном временном каталоге. Игра и сервер не запускаются.

## Границы доказательства

Копия серверного servertest1 и его CVPEquipment.bin в этой проверке недоступны;
ссылка Play2Go требует отдельного доступа. Использована разрешённая альтернативная
проверка на настоящих старых файлах, а не текущий payload с заменённым номером.
Хеш JAR непосредственно на ZomboEEEd не получен: сверена локальная Workshop-копия.
Полный мир не запускался. Native item-проверки используют unowned target seam,
не настоящий WorldDictionary/ScriptManager и не передачу предмета игроку.
43 исторических предмета — простые Rope; расширенная проверка native свойств трёх
материалов в ValidateWorld относится к текущим, а не историческим снимкам.
Это не доказательство восстановления всех тел в servertest1 или устранения проблем входа.
Нужна отдельная проверка на копии конкретного серверного мира перед его обновлением.

Он собран из этой ветки main с исправлением, не установлен и не опубликован.
