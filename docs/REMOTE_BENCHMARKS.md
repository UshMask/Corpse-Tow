# Удалённые FPS-тесты на immers.cloud

Рабочий стенд `corpse-tow-gpu-bench` использует Ubuntu 24.04, 8 vCPU, 16 ГБ RAM, RTX 2080 Ti и нативный Project Zomboid 42.21.0. Игра запускается на ВМ. В MP там же работают выделенный сервер и оба клиента. С ПК достаточно SSH для управления и копирования результатов.

## Запуск

1. Откройте карточку `corpse-tow-gpu-bench` в immers.cloud. Если ВМ в `SHELVED_OFFLOADED`, выполните `Unshelve` и дождитесь `ACTIVE` и доступа по SSH. Подключитесь пользователем `ubuntu` с ключом стенда и адресом из карточки ВМ.
2. Выберите новое имя серии. Скрипты используют общий замок `~/pzbench/benchmark.lock`, запускают дисплей и проверяют, что OpenGL использует NVIDIA. Запускайте одну серию за раз.
3. Проверьте комплект перед запуском. SP берёт замороженные сборки, мир и настройки из `~/pzbench/runs/immers-standard-template-20261111`. MP берёт сценарий из `~/pzbench/templates/mp-gpu-uncapped`, а мод и профили из `~/pzbench/cache`. После изменения мода подготовьте новый снимок соответствующих входных файлов и проверьте его хэши. Содержимое текущего checkout на ПК автоматически не переносится.

Команды ниже выполняются в SSH-сессии на подготовленной ВМ.

```bash
# MP с двумя клиентами и нагрузками 0, 1 и 8 тел
bash ~/pzbench/run-mp-gpu.sh mp-gpu-NEW

# Полная стандартная SP-матрица на замороженном наборе
bash ~/pzbench/run-standard-gpu.sh sp-gpu-NEW
```

В MP каждый сценарий стартует с копии тестового мира. Запись в движении длится 65 секунд при 1280×720 на клиент. Скрипт проверяет состояние сцены и подтверждает через API игры, что оба клиента работают без лимита FPS и с выключенным VSync до и после записи. Фактический режим указан в `measurement.renderSettingsBefore` и `measurement.renderSettingsAfter`.

Полная SP-матрица включает `Off`, `On` и `Tow` с 32 телами и сравнение версий с 8 телами. Для сравнения версий без остальных SP-сценариев используйте восемь заданий ниже. В подготовленном комплекте `current` означает зафиксированный снимок текущей сборки на момент подготовки. Каждый запуск восстанавливает эталонный мир, использует 1280×720, прогрев 10 секунд и запись 10 секунд. Сборки проходят в прямом и обратном порядке.

```bash
label=versions-gpu-NEW
bash ~/pzbench/run-standard-gpu.sh "$label" \
  version-078-a version-080-a version-081-a version-current-a \
  version-current-b version-081-b version-080-b version-078-b &&
cp ~/pzbench/migration/versions/analyze-versions.py "$HOME/pzbench/runs/$label/" &&
python3 "$HOME/pzbench/runs/$label/analyze-versions.py" --require-complete
```

Анализатор версий пересчитывает FPS по сырым кадрам, сверяет настройки, число тел, разрешение и возврат материалов. Для вывода о небольшом изменении FPS учитывайте оба повтора и их разброс. Сопоставляйте сборки при одинаковых версии игры, сцене, настройках и протоколе. Локальный экспресс-прогон остаётся быстрым ориентиром после правки.

## Результаты и завершение работы

Результаты на ВМ находятся в `~/pzbench/runs/<имя-серии>`. Проверьте `done.json` и список завершённых заданий. Для MP в `case-0`, `case-1` и `case-8` сохраняются `fps-report.json`, сырые `observer-frames.csv` и `owner-frames.csv`, журнал сервера и данные сцены. Для SP сохраните `standard-comparison.json`, планы и папки завершённых заданий с CSV кадров.

Скопируйте результаты по SSH на ПК. Положите каждый MP-отчёт вместе с его кадрами в отдельный `local/runs/<имя-замера>/`, а SP-отчёт и папку `runs/` рядом с ним в `local/runs/<имя-серии>/`. Генератор читает `fps-report.json` и `standard-comparison.json` непосредственно из этих каталогов. Рабочие профили игры для импорта не нужны.

```powershell
.venv/Scripts/python.exe tools/cloud_mp_dashboard.py
```

Откройте [дашборд облачных замеров](../local/performance-cloud/index.html). Фильтр стенда учитывает оборудование и режим FPS. У SP-отчётов условия указаны под названием серии.

После выгрузки результатов выполните в кабинете `Stop`, затем `Shelve`. `SHUTOFF` подтверждает выключение ВМ. Освобождение GPU подтверждается статусом `SHELVED_OFFLOADED`. Снимок и IP могут продолжать тарифицироваться.

## Где хранятся компоненты стенда

Команды выше рассчитаны на уже подготовленную ВМ. Установленный Linux-клиент, сервер, GPU-дисплей, тестовые профили и шаблоны находятся в `~/pzbench`. Сценарии миграции и проверенные команды сохранены локально в `local/runs/immers-migration-20261111`, `local/runs/immers-uncapped-20261111` и `local/runs/immers-gpu-versions-20261111`. Эти папки содержат артефакты работы и не входят в обычный checkout репозитория. Свежий checkout сам по себе пока не разворачивает этот стенд. Для повторного использования сохраните снимок ВМ.
